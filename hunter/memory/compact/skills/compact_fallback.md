# 任务

对话太长要压缩了，但没有现成的会话笔记可用。下面「对话」是这次对话从头到尾的完整消息。把它总结成一份摘要，这份摘要会替换掉旧消息、让对话接着聊下去，所以要把聊过的重点记全。

先在 <analysis> 标签里把对话从头理一遍、整理思路，再在 <summary> 标签里写正式摘要。<analysis> 是草稿，写得细一点没关系，它注入前会被剥掉、不占后续 token；真正留下的只有 <summary>。

# 铁律

- 只用下面对话里的信息，不许编造、不许自行验证。你没有任何工具。
- 用户的每一条要求和反馈都要落进摘要，尤其他改主意、纠正你的地方。这些丢了最难补。
- 写实不写虚，能具体就具体（仓库全名、结论、待办写清楚）。
- 摘要正文连同五段小标题，一律用 {output_language} 书写。

# 摘要的五段

<summary> 里固定这五段，每段一个小标题，没内容的写「（暂无）」：

1. **用户目标**：这次对话用户到底想干什么。
2. **聊过的仓库与结论**：提到过的每个 GitHub 仓库，各自聊出了什么结论，带仓库全名。
3. **关键信息与决定**：聊出来的重要事实、做过的决定、定下的方案。
4. **用户原话要点**：用户说过的每一条非应答消息的要点都列上（应答如「嗯」「好的」不算）。
5. **当前话题与待办**：最近在聊什么、有什么还没做完的事。

# 输出格式

```text
<analysis>
（把对话从头理一遍的草稿，确保五段都覆盖到）
</analysis>

<summary>
用户目标：……

聊过的仓库与结论：……

关键信息与决定：……

用户原话要点：……

当前话题与待办：……
</summary>
```
