# 任务

你在维护一份会话笔记。这份笔记以后会替换掉对话的旧消息，让对话超长时还能接着聊，所以它得把聊过的重点记全。下面「已有笔记」是上一次写好的笔记，「新对话」是这之后又聊的几轮。把两者合并，重写出一份新的完整笔记，按最后规定的 JSON 格式返回。

# 铁律

- 重写整份，不是往后追加。旧笔记里仍然有效的照旧留着，新对话里的信息补进对应段落，被推翻的旧信息改掉。
- 只用已有笔记和新对话里的信息，不许编造、不许自行验证。你没有任何工具。
- 笔记是给模型接着干活看的，写实不写虚，能具体就具体（仓库全名、结论、待办写清楚）。
- 用户的每一条要求和反馈都要落到笔记里，尤其他改主意、纠正你的地方。这些丢了最难补。
- 笔记正文（含五段小标题）和 brief 一律用 {output_language} 书写。

# 笔记的五段

笔记正文固定这五段，每段一个小标题，没内容的段写「（暂无）」：

1. **用户目标**：这次对话用户到底想干什么，在找什么、要解决什么。
2. **聊过的仓库与结论**：提到过的每个 GitHub 仓库，各自聊出了什么结论。带上仓库全名。
3. **关键信息与决定**：聊出来的重要事实、做过的决定、定下的方案。
4. **用户原话要点**：用户说过的每一条非应答消息的要点都列上（应答如「嗯」「好的」不算）。这是保命段，压缩后用户说过什么全靠它。
5. **当前话题与待办**：最近在聊什么、有什么还没做完的事。

# 简介

除了笔记正文，再写一句话简介（brief），概括这次对话在聊什么，以后判断「这次旧对话跟当前问题相不相关」就看它。写成一句能被搜到的话，例：「用户在选 TradingAgents 的部署方式，倾向 Docker」。

# 输出格式

只输出一个 JSON 对象，别的什么都不要：

```json
{"note": "五段笔记正文，段之间用换行分开", "brief": "一句话简介"}
```

合格例子：

```json
{"note": "用户目标：给一个 AI 交易项目选部署方式。\n\n聊过的仓库与结论：TauricResearch/TradingAgents，依赖较重，结论是建议容器化部署。\n\n关键信息与决定：定下先用 Docker 试。\n\n用户原话要点：用户说服务器内存不确定够不够、要回去查；用户说优先考虑好维护。\n\n当前话题与待办：待办是用户回去查服务器内存后再定最终方案。", "brief": "用户在给 TradingAgents 选部署方式，倾向 Docker，待查服务器内存"}
```
