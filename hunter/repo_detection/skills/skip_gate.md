# 任务

上面已经给了你这个仓库的 full name、description、topics、README、目录结构树。只根据这些，判断它的整体方向能不能满足下面这些需求。

需求清单是 {keypoints}。

# 判断规则

整体方向明显不符、这个仓库根本不是用户要的那类东西，就跳过它，不再深入读代码。

某条具体需求在上面的信息里没写到，不是跳过的理由，因为很多具体功能 README 不写、要读代码才知道有没有。只有整体方向明显不对才跳过。方向沾边、只是还没确认具体功能，就不要跳过。拿不准就不要跳过。

# 输出

只输出一个 JSON，不要别的话。

要跳过就输出（reason 用 {output_language} 书写）

```json
{ "skip": true, "reason": "一句话说清它是什么、为什么方向不符" }
```

要进深挖就输出

```json
{ "skip": false, "reason": "" }
```

**除此之外严禁你做任何事情。**
